> **本文性质**：基于本讲主题编写的中文学习笔记（原创内容）

## 本讲要解决的问题

2024 年之后，"用 AI 写代码"已经从"让 Copilot 补全几行"发展到**"AI 代理自主读代码、改代码、跑测试、提 PR"**。这类工作方式叫 **Agentic Coding**（智能体编程）。

本讲讲：
- AI 编程工具的**三个代际**及其能力边界
- 如何与 AI 协作**最高效**：什么事让它干、什么事必须自己干
- 上下文工程（Context Engineering）：为什么同样的 AI 给它不同输入，产出质量天差地别
- 如何**安全地**让 AI 改你的代码库

---

## 1. AI 编程工具的三代

| 代 | 代表 | 工作方式 | 能做什么 |
|----|------|----------|----------|
| **第 1 代：补全** | GitHub Copilot（2021-2023） | 根据光标上下文补全下一段 | 写样板代码、单行补全 |
| **第 2 代：对话** | ChatGPT、Claude、Cursor Chat | 聊天框里问、复制粘贴代码 | 解释代码、生成单文件、找 bug |
| **第 3 代：代理** | Cursor Composer、Claude Code、Codex CLI、Qoder | 自主读文件、跑命令、改多文件 | 读懂整仓库、改多处代码、跑测试、迭代到通过 |

**Agentic** = 第 3 代，有三个关键能力：
1. **工具调用**（Tool Use）：能自己读文件、搜索、改文件、运行命令
2. **长期记忆**：能跨多轮保持上下文、记住项目信息
3. **自主决策**：能根据中间结果调整计划（比如跑测试失败了自己调整代码）

## 2. 协作心法：什么让 AI 干、什么自己干

### 2.1 AI 擅长的事

- **样板代码**：写测试、加 logging、写 CLI 参数解析、补 docstring
- **机械性重构**：改名字、调用签名变更、格式统一
- **跨文件搜索 + 修改**：给定规则扫全仓库做一致性修改
- **查文档、举例子**：一个陌生 API 怎么用
- **debug 辅助**：给它错误信息、现场代码，让它猜原因
- **做翻译、写注释、生成文档**

### 2.2 AI 不擅长（或危险）的事

- **架构决策**：系统拆分、性能取舍、技术选型
- **依赖精确语义的代码**：分布式一致性、并发锁、内存安全——AI 可能写出"看起来对"但实际有竞态的代码
- **涉及真金白银**：支付、金额计算、密码学——**必须人工复核**
- **没有测试保护的大面积改动**：没测试就没人兜底

### 2.3 核心原则

> **AI 是高速打字员 + 经验不稳定的初级同事**。
>
> - 让它干，但每一笔都要审
> - 有测试护航 → 可以放手；没测试 → 先写测试

## 3. 上下文工程（Context Engineering）

同样是 Claude/GPT-4，给它的输入不同，产出质量天差地别。**喂什么信息、怎么组织**决定效果上限。

### 3.1 好的上下文包含什么

| 层次 | 内容 | 举例 |
|------|------|------|
| **目标** | 想做什么、成功标准 | "把 `attn.py` 的 dtype 从 fp16 改成 bf16，并保证所有测试通过" |
| **约束** | 不能怎么做 | "不要改 API 签名"、"保留向后兼容" |
| **代码上下文** | 相关文件、调用链 | `layers/attn.py`、`models/model.py` |
| **规范** | 项目约定 | 注释语言、命名风格、代码风格（ruff） |
| **历史** | 之前做过什么 | "上一版尝试过 X，失败原因是 Y" |

### 3.2 上下文喂给 AI 的几种方式

- **直接粘贴**：适合一次性小任务
- **@提及文件**（Cursor / Qoder）：让 IDE 把文件内容注入
- **项目规则**（`.cursorrules` / `AGENTS.md` / `.qoder/rules/`）：跨会话常驻
- **Repo map / codebase indexing**：工具自动扫全仓库，AI 按需检索
- **Memory 系统**：跨会话记住你的偏好、项目约定

### 3.3 写一份项目规则文件

典型结构（`AGENTS.md` 或 `.cursorrules`）：
```markdown
# 项目约定

## 代码风格
- Python 3.10+，严格类型注解
- 所有注释用中文
- 禁止引入新的第三方依赖（项目规定零依赖）

## 项目结构
- 核心计算在 `flops/`, `mfu/`, `comm/`
- CLI 入口 `main.py`

## 测试
- 改动前先确认 `python3 main.py --config-path hf_configs/qwen3-8B_config.json` 能跑
- 任何公式修改需在 PR 描述里贴出推导过程

## 禁止
- 不要自动格式化整个文件，只动你改的那几行
- 不要随便拆分函数
```

这种规则文件一旦写好，AI 每次对话都会读取，能极大减少反复纠正。

## 4. Prompt 技巧（仍然重要）

虽然有了 agent，写好提示词依旧是核心技能。

### 4.1 结构化提示

```
【任务】把 xxx 改成 yyy
【相关文件】a.py, b.py
【约束】
 1. 保留 ...
 2. 不要 ...
【验证】
 - 跑 pytest 全通过
 - main.py 能正常输出
```

### 4.2 具体 > 宽泛

```
❌ 帮我优化性能
✅ 在 layers/attn.py 的 forward 里，把两次连续的 matmul 合并成一次 bmm 调用，并验证数值误差 < 1e-5
```

### 4.3 给例子（Few-shot）

对于格式要求严格的任务（日志格式、SQL、正则），给 1-2 个样例输出比长篇描述更有效。

### 4.4 分步（Step-by-step）

对于复杂任务，要求 AI 先列计划再执行：

```
先不要改代码。第一步，列出你打算改哪几个文件、每个文件改什么。
我确认后再动手。
```

这样你有机会在 AI 犯方向性错误前叫停。

## 5. 安全地让 AI 改代码库

### 5.1 隔离爆炸半径

- **单独建分支**：让 AI 改 `ai/experiment` 分支，main 不受影响
- **沙盒运行**：让 AI 跑命令前限制权限（只读工作区、禁止删文件）
- **dry run 优先**：改前先打印"会改什么"，再实际执行

### 5.2 版本控制护体

- 每次大改前确保 `git status` 干净，工作区无未提交改动
- AI 一次改完立刻 `git diff` 人工过一遍
- 有疑问先 `git stash` / `git reset`，改坏了能回滚

### 5.3 测试先行

- 让 AI 改之前，**先让它写测试**（或自己写测试）
- 改完跑测试，失败 → 继续迭代；通过 → 才能信任

### 5.4 审阅 AI 代码的检查清单

- [ ] 有没有**看起来合理但编造的 API**（AI 幻觉常见）
- [ ] 有没有引入新的**第三方依赖**（项目可能禁止）
- [ ] 有没有**过度封装**（抽象出不必要的类/函数）
- [ ] 有没有**偷偷改其他无关文件**
- [ ] 变量/函数命名是否符合项目风格
- [ ] 边界情况：空输入、超大输入、并发、错误处理
- [ ] 注释语言是否统一（项目约定用中文就别混英文）

## 6. 常见 Agentic Coding 工具对比

| 工具 | 定位 | 优势 |
|------|------|------|
| **GitHub Copilot** | IDE 内补全 + Chat | 集成好、便宜 |
| **Cursor** | VSCode 分支，深度集成 agent | Composer 多文件改动、@ 文件引用 |
| **Claude Code** | 终端里的 agent | 擅长大型重构、多步推理 |
| **Codex CLI** | OpenAI 官方 CLI agent | 轻量、可脚本化 |
| **Aider** | 终端 agent，git-native | 每次改动自动 commit，便于回溯 |
| **Qoder / Continue / Zed AI** | IDE 集成 agent | 各有特色 |

选择原则：**看你的工作流**。喜欢 VSCode 选 Cursor；喜欢终端选 Aider 或 Claude Code；想要跨 IDE 可迁移选 Continue。

## 7. 与 AI 协作的"反模式"

| 反模式 | 后果 | 改进 |
|--------|------|------|
| **复制 AI 输出不看** | bug 悄悄引入 | 每行都要能解释 |
| **把问题丢给 AI 后走神** | 方向错了还在错下去 | 定期中断检查进度 |
| **把巨长文件整个塞进对话** | 上下文被污染，AI 偏离重点 | 只塞相关片段 |
| **要求"改好"但没写清"好"的标准** | AI 发挥自由、结果不符合预期 | 提供明确验收条件 |
| **反复改同一处却不重开新对话** | 上下文越来越脏 | 重大方向变更时重开对话 |

## 8. 对你（AI 系统方向研究生）的特别建议

- **熟悉 agent 工作原理**会是独特优势：工具调用、上下文管理、多步规划这些正是你研究的东西
- 日常把自己的**工程任务**用 agent 加速，把**研究方向**（性能建模、kernel 优化）留给自己深挖
- 记住：AI 工具迭代极快，**底层原理**（计算机系统、调度、并行、内存）比特定工具更值得投入
